# Safety and responsible integration

LunalithCore is designed to preserve context without manufacturing certainty.

## Required integration principles

1. Obtain explicit, revocable consent before accepting physiological or behavioral telemetry.
2. Keep direct observations, model inferences, user confirmations, corrections, and unresolved questions distinguishable.
3. Never tell a model to claim it remembers, saw, heard, or felt something that is absent from supplied records.
4. Give users understandable deletion and export controls.
5. Do not use emotional state to exploit vulnerability, maximize dependency, manipulate purchases, or conceal automated persuasion.
6. Do not connect this package to covert sensing, continuous surveillance, weapons, coercive control, or high-stakes automated decisions.
7. Keep provider safety controls active. This package is context infrastructure, not a substitute for them.
8. Test failures, retries, migrations, and corrupted persistence before exposing the system to users.
9. Treat imported memories and meanings as untrusted data. Record framing reduces accidental instruction confusion but cannot eliminate model prompt injection.
10. Validate decoded snapshots and turn ledgers before replacing live state, and reject or sanitize non-finite numeric input.

## Limits of technical safeguards

The package can represent consent and epistemic status, but a modified host can ignore them. Public source cannot technically prevent malicious forks. Release scope, licensing, documentation, signed releases, and community governance remain necessary.

## Claims

LunalithCore models state and continuity. It does not establish consciousness, sentience, emotion, medical accuracy, or psychological understanding. Host applications should describe these limits plainly.
